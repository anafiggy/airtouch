# AirTouch 品牌官网 V23

## 本次更新

- 移除 V22 生硬的白色文案遮罩，不再通过任何遮罩、蒙层或白色矩形解决首屏重叠。
- 桌面端重构为真正的双栏网格：左侧只放动态标题、说明和按钮，右侧只放手机与钥匙扣演示，两栏不会互相覆盖。
- 首屏改为全宽白色背景，并仅在产品区域加入非常轻的紫蓝环境光，不再出现局部白板边界。
- 960px 以下改为上下布局，产品演示成为正常文档流中的第二行，不再绝对定位到文字下方。
- 取消所有首屏 `mask-image`、全局伪元素遮罩和文案背景伪元素。
- 更新版本标记为 `airtouch-build=V23-20260728`，方便部署后核对缓存。
- 保留 V16 手机触碰动画、动态标题、场景内容、移动端导航和飞书表单逻辑。
- 修复 GPT 内置浏览器与 Chrome、Safari、Edge 等外部浏览器中首屏遮罩结果不一致的问题。
- 完全取消覆盖整个首屏的 `hero::after` 全局遮罩，右侧手机和钥匙扣不再经过任何半透明层。
- 左侧文案使用自身的局部白色背景与窄渐变边缘，不依赖负层级遮罩，减少不同浏览器的层叠上下文差异。
- 移除首屏产品演示上的 `mask-image` 与 `-webkit-mask-image`，避免浏览器内核对遮罩合成方式不同。
- 移动端继续使用文案局部的纵向渐隐，但不会修改产品演示本身的透明度。
- 在 HTML 中加入 `airtouch-build=V22-20260728` 版本标记，便于判断 EdgeOne 是否仍在返回旧缓存。
- 保留 V21 的动态标题、V16 触碰演示、移动端布局和飞书表单逻辑。
- 重构首屏遮罩逻辑：遮罩从覆盖整块首屏改为只保护左侧文案的局部阅读层。
- 桌面端将左右过渡区压缩到约 15% 的窄带，过渡结束后右侧产品保持原始对比度和清晰度。
- 取消右侧演示区域的二次洗白，仅在首屏底部保留轻微渐隐，避免与下一模块产生硬切。
- 调整右侧演示的位置与宽度，让手机和钥匙扣完整进入高对比度区域。
- 移动端不再用整屏白色遮罩覆盖产品，而是由文案区域自身向下渐隐；产品演示透明度由约 50% 提升到接近完整显示。
- 保留 V20 的手机触碰、NFC 光波、系统桌面和企业官网切换动画。
- 首屏右侧恢复 V16 的手机靠近物料、触碰识别和界面切换效果。
- 移除 V19 写实合成图及其分层移动方式，避免产品轮廓和运动关系显得僵硬。
- 右侧手机触碰前显示系统桌面，触碰后打开企业官网；动画与 NFC 光波保持同步。
- 重新划分首屏左右区域：右侧演示进一步右移，左侧动态标题拥有独立白色阅读底层。
- 桌面端增加横向渐变隔离区，移动端增加纵向渐隐遮罩，避免右侧画面和左侧文字相互覆盖。
- 手机页面只保留“企业服务中心”等功能性界面文字，不再重复左侧的核心价值文案。
- 修复首屏左侧文字被渐变遮罩覆盖的问题：遮罩现在只位于写实产品图之上、标题和按钮之下。
- 将写实主视觉拆成独立的手机层、钥匙扣层和屏幕界面层，不再移动整块背景图片。
- 手机加入“靠近—触碰—打开官网—复位”的 6 秒循环动作；钥匙扣保持静止，触碰时出现 NFC 反馈光波。
- 手机移动与屏幕状态使用同一时间轴：触碰前显示系统桌面，接近钥匙扣后切换为企业官网。
- 产品图仍然作为首屏即时背景优先出现，脚本接管后才无闪烁地切换为独立动画图层，兼顾清晰度和加载速度。
- 窄屏使用幅度更小的触碰动作，避免手机进入标题阅读区域；开启“减少动态效果”时显示静态触碰完成状态。
- 首屏手机与钥匙扣完全改为 1536 × 1024 的高分辨率写实产品渲染，不再使用卡通 CSS 设备。
- 写实主视觉直接嵌入首屏样式并优先显示，不再等待整份 HTML 解析完成后由脚本创建，改善 PC 端打开时的延迟。
- 首屏演示区继续右移，手机与左侧标题、正文之间保留更明显的安全距离。
- 增加真正位于产品图上方的渐变遮罩；桌面端从左向右过渡，移动端从文字区向下渐隐。
- 手机黑色屏幕上叠加独立界面：初始显示系统桌面，触碰后切换为企业官网。
- 页面初始 HTML 直接包含第一组动态标题，避免脚本加载前短暂显示旧标题或空白。
- 动效精简为手机界面切换和 NFC 光波反馈，减少首屏绘制压力。
- 首屏视觉整体右移，与左侧文字形成清晰分区，不再落在标题和正文正下方。
- NFC 圆形物料升级为带金属环和连接扣的 AirTouch 钥匙扣造型。
- 手机向右靠近钥匙扣，触碰距离更自然，手机与物料之间的关系更明确。
- 手机触碰前显示完整的系统桌面；触碰后自动打开企业官网页面，不再只显示抽象的成功提示。
- 参考轻流官网的首屏层级，在桌面端增加左右留白边界，在窄屏增加渐变遮罩，让文字和产品演示自然分开。
- 重新设计 1120px、900px、760px 和 420px 下的首屏构图，手机端不再直接压缩桌面布局。
- 完全移除 V15 通过裁切整张海报制造的首屏动效。
- 手机、NFC 物料、触碰光波和手机界面全部改为独立图层，不再出现未抠干净的背景。
- 首屏使用“靠近—识别—开启服务”的 5.8 秒状态循环，手机界面在触碰后切换为成功状态。
- 手机与物料采用浏览器原生高清图形绘制，在 Retina 和高分辨率屏幕上保持清晰，不依赖放大低清位图。
- 动效只使用位移、旋转与透明度变化，兼顾流畅度；系统开启“减少动态效果”时显示静态成功画面。
- 首屏标题升级为动态价值表达：“让一次触碰，变成”后依次输入“持续互动的入口”“继续跟进的线索”“反复触达的客户”。
- 移动端采用专门的紧凑信息架构：优势卡片和交付步骤横向滑动、场景媒体缩为双图组合、二维码隐藏，减少连续下滑距离。
- 修正手机端强制不换行导致的标题、正文和数据溢出。
- 标题在桌面端保持语义完整，在窄屏上根据可用宽度自然换行。
- 重构优势卡片、物料 Tab、场景方案、客户案例、交付流程和联系表单的手机布局。
- 为 760px、480px 和 360px 三档屏幕宽度分别设置稳定的响应式规则。
- 图片、表单控件、联系方式、案例指标和弹窗均限制在手机可视区域内。
- 导航栏改为固定在页面顶部，页面跳转或向下浏览后仍可随时使用。
- 修复移动端菜单，支持触屏开关、点击导航后收起、点击外部收起和 Esc 键关闭。
- 保留 V13 已经打通的飞书多维表格写入和群机器人通知逻辑。
- 所有网页图片已嵌入 `index.html`，无需单独上传图片目录。

## EdgeOne 部署

仓库根目录请至少保留：

```text
index.html
edge-functions/
  api/
    lead.js
```

`index.html` 为单文件前端，大小约 11 MB，低于 GitHub 网页上传 25 MB 的单文件限制。`lead.js` 负责把表单线索写入飞书多维表格并发送群通知，请继续保留现有 EdgeOne 环境变量。

## 表单错误诊断

最新版 `lead.js` 会在失败响应中附带不含密钥的诊断字段：

- `MISSING_ENVIRONMENT`：生产环境缺少必要变量。
- `FEISHU_AUTH_FAILED`：App ID 或 App Secret 无效。
- `FEISHU_BITABLE_WRITE_FAILED`：多维表格权限、App Token、Table ID、字段名称或字段类型不匹配。
- `LEAD_SUBMISSION_FAILED`：其他运行时或网络异常。

同时会返回 `providerCode` 和 `requestId`，便于进一步定位；不会返回 App Secret 或访问凭证。
